# Rune — Roadmap

Status as of 2026-10-09 (post-cutover to the native, single-process architecture). See [README.md](README.md) for the architecture overview.

## Done (in `native/`, the current app)

- Document I/O: `.odt` native read/write; `.docx`/`.doc` via a `soffice` batch-conversion bridge, async (doesn't block the UI), verified against real-world files not just our own writer's output
- Full text editing: keyboard, mouse, clipboard — all native `TextEdit` behavior, not custom-built
- Formatting: Bold/Italic/Underline, paragraph styles with named/inherited style resolution on import (`styles.xml` + `content.xml` automatic-styles, parent-style-name chains), bullet/numbered lists with promote/demote nesting, alignment, font family/size, text color
- Tables: insert, insert/delete row, insert/delete column, Tab/Shift+Tab cell navigation
- A save-time sanitizer that works around a real Qt ODF-writer bug (a table directly after a list gets silently dropped by LibreOffice on import otherwise) — verified with a direct A/B test, not just a scratch-document assumption
- `.docx` round-trips verified against `samples/test.docx`/`test.doc` (real files, not generated by this codebase) with real `soffice` conversion as the independent check

## Known limitations — found, tested, and documented, not guessed

| Limitation | Why |
|---|---|
| **Nested tables lose the inner table's content on export** | Confirmed via HTML export (plain-text conversion doesn't reliably represent nested structures). Rare pattern in practice; lower priority. |
| **List numbering restart, custom start values, bullet characters, number formats** | Imported lists always get the UI's own level styles rather than preserving the source document's exact numbering presentation. |
| **Table/column widths, cell borders, backgrounds** | Not read or written. |
| **`styles.xml`'s own automatic-styles (headers/footers) and default-style** | Not read — only named paragraph styles with `style:parent-style-name` chains. |

## Not started

| Feature | Notes |
|---|---|
| **AI integration** | The actual point of this project. Nothing built yet — see below. |
| **Images** | No insertion, no text wrap, no import/export at all |
| **Headers & footers** | Including "different first page," "different odd/even," "link to previous" |
| **Section breaks** | Mixed page orientation, independent headers/margins per section, restart page numbering |
| **Tab stops & leader lines** | Needs a ruler widget |
| **Table of Contents / outline navigation** | Builds on existing paragraph styles |
| **Exact paragraph spacing / keep-together / widow-orphan** | Was a documented LibreOfficeKit limitation in the old architecture; not yet investigated against `QTextBlockFormat`'s own capabilities in the new one — may actually be achievable now since we're not routing through `.uno:` commands anymore. Worth a fresh look. |
| **Find/replace** | Not built |
| **Spell check** | Not built |
| **Undo/redo UI** | `QTextDocument` has full undo/redo support natively; needs toolbar/shortcut wiring |
| **File → Open / Save As dialogs** | No file picker yet; `openFile()`/`saveFile()` exist and work, just not wired to a picker UI |
| **Command palette (Ctrl+K)** | Where rare actions should live instead of permanent toolbar space |
| **Multi-page rendering / pagination** | The old LOK engine rendered actual paginated pages; `QTextDocument`'s `TextEdit` is a continuous scroll by default — whether Rune needs true pagination (vs. a continuous-document model like most modern editors) is an open product question, not just an engineering gap |

## AI integration (the actual differentiator)

Nothing built yet in the native app. The old LOK-based `engine/`'s AI provider skeleton (Claude/ChatGPT/Grok registry, token storage, no real HTTP calls) lives in `legacy-lok/` for reference but wasn't ported — the right design for this should be native-app-first, not a port of the old engine's command-dispatch pattern.

- [ ] Real OAuth flows for Claude, ChatGPT, Grok
- [ ] Streaming HTTP responses into the document or a sidebar
- [ ] Three interaction modes per the original architecture plan: inline edit, sidebar chat, draft generation
- [ ] A UI dock for AI chat (and potentially a future "inspector" panel for deep formatting controls)

## Architecture notes for contributors

- `native/` is the current app — single process, `QTextDocument`-based. `DocumentController` is the QML-facing API; `OdfReader`/`DocxBridge` are plain C++ (not QML-exposed) handling import and the `.docx` bridge respectively.
- `legacy-lok/` is the **retired** two-process LibreOfficeKit implementation, kept for reference only. See `legacy-lok/README.md`.
- Run `native/build/rune --auto-test` (headless, `QT_QPA_PLATFORM=offscreen`) after any change — 158 checks covering formatting, tables, lists, save/load round-trips verified via real `soffice` conversion, and an empirical proof the `.docx` bridge doesn't block the UI thread.
- **Verify Qt/ODF API behavior against real files before relying on it.** This project has twice found real, silent-failure bugs this way: Qt's ODF writer mangling list-then-table structure (confirmed via `xmllint` + a direct A/B `soffice` conversion test), and earlier, the old LOK engine's `.uno:` commands that returned `ok` while silently doing nothing (confirmed via tile-diffing before/after). Don't assume an API's documented behavior is what actually happens on disk — test it.
