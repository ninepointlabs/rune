Why

AI is not a plugin here.

Every other word processor on Linux treats AI as an afterthought — a sidebar chat window stapled onto software that was finished before large language models existed. Rune starts from the opposite premise. The model is a writing primitive, on the same level as bold, italic, and paste.

Highlight a paragraph and ask Claude to tighten it. Place your cursor and have GPT draft the next section. Switch providers mid-document. This is the actual point of the project — everything else is table stakes.

ODF-first, Word-compatible.

Rune's native format is ODF — open, documented, and the thing Rune's own engine understands directly. Word documents are supported too, but as a conversion at the boundary: open a .docx and Rune converts it once; save as .docx and it converts back. Your working format while you edit is never locked to a proprietary spec.

The engineering budget goes into the editing experience and the AI integration, not into chasing Word-format compatibility as the product's center of gravity.

Native, not a bitmap.

Rune is a single process built directly on Qt's text engine — no tiled bitmap rendering, no inter-process protocol, no serialization standing between your keystroke and the screen. Real incremental text layout, the way a native app should feel.

Built for Omarchy's keyboard-first, minimal aesthetic.

Architecture

One process, native all the way down

Built directly on Qt's QTextDocument — no bitmap tiles, no IPC, no serialization. ODF is the native format; Word documents are a one-shot conversion at the boundary, not the live model.

Status

Early, and honest about it

Core editing works end to end. The AI integration — the actual reason this project exists — is still a provider registry waiting for real HTTP calls.

Some things we tried and couldn't make work — Qt's own ODF writer silently drops a table placed directly after a list, nested tables lose content on export — are documented with the evidence, not hidden. See the full roadmap for the complete, current picture.

Get it

Build it yourself

Arch / Omarchy, with Qt 6 and QuaZip already in the official repos.

# dependencies $ sudo pacman -S qt6-base qt6-declarative quazip1-qt6 libreoffice-fresh # build $ git clone https://github.com/ninepointlabs/rune.git $ cd rune && cmake -S . -B build -G Ninja && cmake --build build # run $ ./run.sh samples/test.docx
